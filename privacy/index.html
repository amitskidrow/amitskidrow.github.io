Privacy policy

Google Drive access, credential storage and website hosting for ssdrive-laptop and related personal recovery tools.

At a glance

The terminal tools operate on the account owner's authorized machines. Google Drive stores the transferred files and backups. This informational website has no sign-in form and does not receive Drive files, OAuth tokens or encryption keys.

1. Scope and operator

This policy covers the personal Google Drive connection, transfer and encrypted recovery utilities using the Google authorization project associated with ssdrive-laptop. They are maintained and operated by amitskidrow. It also covers this informational website, hosted on GitHub Pages.

2. Google permissions and data accessed

The tools use Google's OAuth authorization flow through rclone. The account owner chooses an account and approves the permissions in Google's browser interface.

The configuration can request the full Google Drive scope, https://www.googleapis.com/auth/drive. This permission can allow reading, creating, editing and deleting Drive files. It is broader than permission limited to files created by this application, and is not an account-level restriction to one folder.

Intended operations include checking storage capacity and access to configured destinations; listing or inspecting file and directory metadata; uploading selected files and encrypted backup data; downloading and verifying stored data; and managing backup data according to the operator's configuration.

The data involved may include file contents, names, identifiers, directory paths, sizes, checksums, timestamps and storage-usage information. Credentials include an OAuth client configuration, access tokens and refresh tokens. The tools do not request the account's Google password; sign-in and any two-step verification happen with Google.

3. How the data is used

Google data is used to carry out the personal file-transfer, connection-health and recovery functions described above. It is not sold, used for advertising or used by these utilities to train artificial intelligence or machine-learning models.

Use of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

4. Where processing and storage happen

Processing takes place on devices or infrastructure authorized and controlled by the operator. Local files, staging copies, operational receipts and configuration remain in the locations selected by the operator. Uploaded data is stored in the chosen Google Drive account.

OAuth tokens and encryption keys are kept in private local configuration. Setup may create private candidate configurations and recovery copies of the existing configuration. A refresh token allows rclone to renew access without a new browser sign-in while the grant remains valid. This website never receives those credentials.

The supported media workflow uses rclone crypt to encrypt contents before upload and decrypt them during retrieval. Related recovery workflows encrypt backup data. Encryption keys must be retained by the operator. Encryption does not hide all metadata from Google, including account information, transfer timing and stored sizes; the protection of names depends on the selected encryption configuration.

5. Sharing, providers and human access

The operator can access the account and files they control. These utilities do not provide a public file-browsing service or share private files with other site visitors. Data is transmitted to Google for the authorized Drive operations. When the operator runs a tool on hosted infrastructure, that infrastructure provider's processing is also subject to its own terms and policies.

Google's handling of account and Drive data is governed by the Google Privacy Policy. This policy describes these utilities; it does not replace the policies of Google, GitHub or infrastructure providers.

6. Website visits

This site serves static information. It does not run application analytics, advertising, tracking pixels or embedded credential forms, and it does not make Google Drive API requests from the visitor's browser. It does not set application cookies.

GitHub Pages hosts the site. GitHub logs visitor IP addresses for security purposes, whether or not a visitor is signed in to GitHub. GitHub's handling of hosting data is covered by the GitHub General Privacy Statement. Following an external link is subject to that destination's policies.

7. Retention, removal and revoking access

Files in Drive remain until the account owner deletes them or a configured backup-retention operation removes them, subject to the provider's retention and trash behavior. Local downloads, decrypted staging files, logs, configuration and configuration backups remain until removed by the operator or the relevant tool's documented retention rules.

The account owner can revoke the application's access through Google Account third-party connections. Revocation prevents future access using that authorization; it does not itself delete local copies or files already stored in Drive. Removing the software also does not necessarily remove its configuration, credential backups or existing files.

To remove the locally retained data, the operator must remove the relevant files and credential/configuration copies from their authorized machines. To remove the stored cloud data, the operator must delete the corresponding Drive files or backup repository data.

8. Contact and updates

For questions or privacy requests, contact the maintainer through the website repository's issue tracker or GitHub profile. Do not include tokens, client configuration JSON, encryption keys or private media in public messages.

Changes to this policy will be published on this page with an updated effective date. Review it before authorizing a new version of the tools.
